# Phase 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A rest countdown in the Workout dock derived from set timestamps, an optional effort rating and pain flag at the end of each exercise, and a weekly Markdown summary file shared from Home.

**Architecture:** Three small pure modules with Vitest tests carry the logic: `src/rest.ts` (what the dock shows after a tick), `src/week.ts` (Singapore calendar weeks and day labels from date strings, no `Date` local-time arithmetic), and `src/weekly.ts` (the Markdown document from the same raw tables the JSON export reads). The Workout screen's existing one-second `now` state drives the dock; nothing new is stored for the timer. The export sheet's body becomes a shared `FileSheet` component so the weekly sheet reuses share, copy and the plain-http fallback.

**Tech Stack:** Vite 8, React 19, TypeScript, Dexie 4, plain CSS, Vitest 4. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-31-phase2-design.md`

## Global Constraints

- One tap per set stays: the dock ✓ keeps its 64 px size, position and behaviour in every rest state.
- Every control added is at least 56 px in the thumb direction (`var(--tap)`); chips use the existing `.chip` class.
- The timer is a pure function of set rows and the current time. No new timestamp is written for it, no running counter is kept.
- Rest constants: 60 s after a set, 120 s after the last set of an exercise, display window target + 300 s.
- Singapore time everywhere: dates and week boundaries come from the `YYYY-MM-DD` prefix of stored `+08:00` strings, never from the machine's local time zone.
- Export JSON: `schema` stays `gymlog/1`; set objects gain only `rpe` and `pain`, and only when present.
- No Dexie version bump. No seed changes. No network use.
- `prefers-reduced-motion: reduce` disables the ring animation; numerals still update.
- No em or en dashes in any text the app or the file shows.
- Commit after each task on `main`. Never push: every push deploys the live site and Shafi approves each push.

## Review Focus

1. Two ticks stored with the same `completedAt` second (dock ✓ then row ✓ within one second): the last tick must be the later `seq`, not an arbitrary one. Pinned in Task 1.
2. A `completedAt` later than `now` (phone clock moved back): elapsed must clamp to 0, not show a negative or huge count. Pinned in Task 1.
3. The ISO year differs from the calendar year at the year boundary: 1 Jan 2027 is in 2026-W53 and must not produce `2027-W01` or `2027-W53`. Pinned in Task 4.
4. Set rows pointing at an exercise pruned from the library (seed removal) must not throw or appear in the weekly file. Pinned in Task 5.
5. Finishing during the drink-up window deletes unticked rows of a just-added exercise, but the rating already written on the last tick must survive. Pinned in Task 3 (writes go through `saveRow`, which persists immediately) and checked in the Task 3 browser step.

`weeklySummary(data, week, generatedAt)` builds the sections in order and joins with blank lines:

- Header: `# Gym Log · week ${week.week} · ${dayLabel(week.start)} to ${dayLabelYear(week.end)}` and the fixed Generated line with `dayLabelYear(dateOf(generatedAt))` and `generatedAt.slice(11, 16)`.

Strength rows: duration `minutesBetween(startedAt, endedAt)` + ` min`, sets = completed rows of that workout whose exercise exists, volume `volumeKg(rows, exerciseMap).toLocaleString('en-SG') + ' kg'`. Cardio rows: the session from `data.cardio` by `workoutId`; duration `${durationMin} min`; Sets `CARDIO_LABELS[modality]`; Volume the non-empty of `avg n`, `max n` joined by ` · `.

Headings for keys with at least one row in the week, ordered by the earliest in-week `completedAt`. Heading suffix for keyed exercises: ` (${shortOutlet(outletName(equipment.outletId))} machine)`. Session bullets: group that key's rows by `workoutId`, order by workout `startedAt` descending; in-week ones first and wrapped in `**`, then up to three with `startedAt` before `week.start`. Bullet text: `${dayLabel(date)} · ${formatSession(ex, rows)}` then ` · RPE n` and ` · back|knee` from `ratingOf(rows)`. Warm-up rows are passed to `formatSession` (which drops them) and to `ratingOf`.
- Muscle line: for each in-week completed working row with a known exercise, add 1 to every chip in `new Set(ex.primaryMuscles.flatMap(chipsFor))`. Output all `CHIPS` sorted by count descending, ties by `CHIPS` order, as `Legs 4 · Chest 0 · …`. Omit the section when the week has no strength sets at all.
- Cardio: sessions whose workout is in the week, by `startedAt` ascending. Segments: day label, seed modality `name`, `${fmt(durationMin)} min`, `${fmt(speedKph)} km/h at ${fmt(inclinePct)}%` when either exists (drop the missing half), followed by ` (int i: v km/h)` / ` (int i: v%)` for each interval where `isOverridden` is true, `peaks a, b, c` for intervals with `peakHr`, `avg n`, `max n`, `RPE n`. Joined by ` · `.
- Bodyweight: entries with `date` in the week, ascending: `${dayLabel} · ${kg} kg` + ` · waist ${waistCm} cm`. Then the comparison: for the latest in-week entry at date L, candidates are entries with `daysBetween(date, L)` between 25 and 31; choose the one nearest 28 (earlier wins a tie); line `- Four weeks ago (${dayLabel}): ${kg} kg. Change: ${delta}` with delta `−1.2 kg` (U+2212) when negative, `+0.8 kg` when positive, `0.0 kg` when zero, one decimal.
- Notes: finished workouts in the week with a non-empty `notes`, ascending, `- ${dayLabel}: "${notes}"`.
- `weeklyFileName(week)`: `gymlog-week-${isoYear}-W${String(week).padStart(2, '0')}.md`.
